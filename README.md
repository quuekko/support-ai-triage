# AI-обробка звернень

Міні застосунок для внутрішньої служби підтримки. Додає звернення, зберігає їх у базі та отримує структурований аналіз від OpenAI або Anthropic. Інтерфейс українською. Без залежностей npm; Node.js 22+.

## Локально

```bash
cp .env.example .env
# заповніть облікові дані та AUTH_SECRET, а також OPENAI_API_KEY або ANTHROPIC_API_KEY у .env
npm run dev
```

Відкрийте http://localhost:3000. Локально дані зберігаються в `.data/support.sqlite` через вбудований `node:sqlite`. `npm test` перевіряє аналіз, зберігання, вхід та права доступу.

## Вибір AI

У панелі адміністратора в блоці «Налаштування AI» оберіть Google Gemini, OpenAI або Anthropic Claude. Вибір застосовується до наступного аналізу; автоматичного переходу на іншого провайдера немає.

Для Gemini створіть ключ у https://aistudio.google.com/apikey та заповніть `.env`:

```dotenv
AI_PROVIDER=gemini
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.1-flash-lite
```

Перезапустіть сервер після зміни `.env`. `AI_PROVIDER` задає початковий вибір (`gemini`, `openai`, `anthropic`); для інших сервісів використовуються `OPENAI_API_KEY` та `ANTHROPIC_API_KEY`. На Vercel задайте ці змінні в Environment Variables та зробіть redeploy. Ключі не повертаються браузеру. Gemini використовує [generateContent зі структурованою відповіддю](https://ai.google.dev/api/generate-content); доступність безкоштовної квоти залежить від моделі й проєкту.

## Вхід і ролі

Тести (`npm test` або `node --test`) використовують окрему SQLite-базу в пам’яті кожного тестового процесу. Вона зникає після завершення тестів. Робоча `.data/support.sqlite` та Supabase під час тестів не використовуються, навіть якщо серверні змінні середовища задані.

Ім’я користувача задається на сервері через `USER_NAME` у `.env` (1–120 символів); якщо значення не задане, використовується `USER_LOGIN`. Користувач не може редагувати ім’я у формі. Сервер сам визначає автора за сесією та відхиляє передане чуже ім’я з кодом 403. Створювати звернення може лише користувач; адміністратор переглядає їх і запускає AI-аналіз. Спроба адміністратора створити звернення через API повертає 403. Зміна `USER_NAME` впливає на нові звернення; історичні записи зберігають початкове ім’я.

- `/login` — вхід користувача; `/` — створення та перегляд власних звернень.
- `/admin/login` — вхід адміністратора; `/admin` — усі звернення та AI-аналіз. Чернетки AI доступні лише адміністратору.
- У `.env` задайте `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `USER_LOGIN`, `USER_PASSWORD` та випадковий `AUTH_SECRET` довжиною щонайменше 32 символи. Для генерації секрету: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
- Підтримується один налаштований обліковий запис кожної ролі; самостійної реєстрації немає. Паролі мають бути різними й надійними. Без налаштувань вхід недоступний.
- Підписана сесія діє 8 годин у cookie з `HttpOnly` і `SameSite=Strict`; у production також `Secure`, тому потрібен HTTPS. Зміна пароля або секрету скасовує чинні сесії. Вихід видаляє cookie з браузера.
- Звернення користувача прив’язані до логіна на сервері та доступні з різних браузерів. Зміна логіна створює інший простір. Попередні демонстраційні звернення з браузерними ID доступні адміністратору, але автоматично користувачу не призначаються.

## Деплой на Vercel

1. Створіть проєкт Supabase та виконайте `schema.sql` у SQL Editor.
2. Імпортуйте цей репозиторій у Vercel як **Other** (без build command). Root directory — корінь репозиторію, Output directory — порожнє поле.
3. Додайте змінні `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, усі п’ять змінних входу з розділу вище та один із `OPENAI_API_KEY` або `ANTHROPIC_API_KEY` до Vercel Environment Variables. Не додавайте ключі з префіксом `NEXT_PUBLIC_`.
4. Deploy. Перевірте додавання звернення, перезавантаження сторінки та AI-аналіз.

API: `GET /api/requests`, `POST /api/requests`, `POST /api/requests/:id/analyze`, `GET /api/health`. Для локального тесту ключ можна ввести в інтерфейсі: він передається лише на сервер для поточного аналізу і не зберігається. На публічному деплої ключ має бути лише у змінних середовища.

### Межі прототипу

Для публічного сервісу з багатьма користувачами потрібні сховище облікових записів, відновлення пароля та розподілене обмеження спроб входу. Поточна версія використовує два серверні облікові записи. Якщо LLM ключ не заданий, аналіз поверне зрозумілу помилку замість вигаданого результату.
